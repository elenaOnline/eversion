# Evidence extraction manifest

Prepared 2026-10-07. This is editorial extraction of seven supplied research reports, not fresh browsing, runtime testing, architecture design, or independent verification of every upstream claim. The underlying reports date their research to 2026-10-07.

## Method

Paragraph-level selection retains documented mechanisms, author-reported implementations, source-inspection details, exact source links, lifecycle/security constraints, uncertainties, and factual corrections. Mixed paragraphs were edited to remove prescriptions while retaining factual content. Every retained passage has an original file/line marker. The JSON ledger records every source paragraph, including omitted passages by location and reason; it does not reproduce withheld content.

No ranked adapter order, recommended product abstraction, proposed architecture, recommended implementation sequence, prototype acceptance target, product judgment, or suggested thesis is part of the research reading set. Descriptions of architectures of actual third-party systems remain, and draft designs of third-party systems are explicitly distinguished from inspected code. Mechanisms are retained without ranking capture, in-process instrumentation, framework introspection, native embedding, browser embedding, proxying, remote sessions, or cooperative component systems.

## What was withheld

- Native: opening recommendation, proposed planes/contract, prototype plan, product conclusion, and implementation prescriptions embedded in mechanisms; factual liveness/input/hierarchy limits extracted separately
- Web: recommended foundation, implementation architecture, browser-fork recommendation, adapter hierarchy, authentication strategy, prototype plan, and solution-oriented failure-case table; documented mechanisms and specific limits retained
- Precedents: bottom-line rankings, “Lesson” evaluations, desktop translation of game implementations, product/research synthesis, fidelity rubric, evaluation proposal, and recommended reading order
- Modding: opening feasibility/product assessment, desktop translation/component contract, inference paragraphs recommending adaptation strategies, recon/maintenance strategy, safety design prescription, and suggested thesis
- Semantics: proposed sidecar architecture, preferred interface ordering, event/command schema, ownership/transaction implementation strategy, workflow prescriptions, acceptance targets and product judgment; documented APIs, failure examples and bounded semantic limits retained
- Report: architecture and product synthesis, personal references and duplicated evidence; retained additions include corrected WinCuts remote-sharing scope and Neovim remote-UI facts
- Critique: main judgment, architectural proposal, demonstration plan and recommended conclusion; retained API details, correction qualifiers and recent factual checks

## Corrections and qualifications retained

- WinCuts local interaction versus read-only remote sharing; source text corrected using the report’s paper-backed qualification
- SkyCraft inspected mesh/atlas protocol versus an explicitly draft GPU texture/depth design
- CEF current accelerated-render source interfaces versus stale general-use prose
- Closed shadow roots are not an absolute privileged-extension inspection barrier
- BrowserBox current proprietary core versus separately licensed Hyper-Frame
- Current Link Audio support and Google Docs suggestions/comments support
- Mac App Sandbox AX-client limits versus exposing an app’s own accessibility
- Chrome active-session consent applies to that specific connection flow
- Missing AX/public APIs are not proof that all permitted runtime channels lack semantics

The original research did not install/run the projects, benchmark composition, establish universal application compatibility, or measure adapter generation. Public repositories and vendor documents demonstrate schemas and documented capabilities, not correctness of every implementation path. Illustrative failure scenarios are not incidents measured in this study. Time-sensitive claims require rechecking before implementation or publication.
